# Nova Machine — جهاز PC حقيقي داخل NovaOS

NovaOS لم يعد محاكاة شكلية: نافذة **«محاكي الحاسوب»** تُقلع جهاز x86 فعلياً.

## ماذا يعمل الآن

| الطبقة | التقنية | الحالة |
| --- | --- | --- |
| المعالج | v86 (JIT → WebAssembly) | ✅ يعمل |
| BIOS | SeaBIOS + Bochs VGA BIOS | ✅ يقلع من قرص المرن |
| الشاشة | Bochs VBE (DISPI 0x1CE/0x1CF) 640×400×8، framebuffer خطي على `0xE0000000` | ✅ |
| المؤشر / لوحة المفاتيح | PS/2 عبر v86 (التحكم بعنوان الشاشة) | ✅ |
| الصوت | PC Speaker (PIT channel 2) | ✅ |
| الأقراص | قرص مرن مرفق (NovaDesk / FreeDOS) + رفع IMG/ISO من جهاز المستخدم | ✅ |

## نظام NovaDesk (مكتوب من الصفر)

`os-image/` يحتوي نواة 32-bit كاملة لا تعتمد على أي نظام جاهز:

- `boot.S` — قطاع إقلاع 512 بايت: تشخيص على المنفذ التسلسلي، تحميل النواة عبر CHS، A20، GDT، قفز إلى 0x10000.
- `entry.S` — إعادة برمجة PIC، 32 stub للأعطال، PIT 100Hz، مقاطعات لوحة المفاتيح والماوس، دوال cdecl للطباعة على COM1.
- `kernel.c` — نواة + واجهة رسومية: خلفية، أيقونات، نوافذ قابلة للسحب والطي، شريط مهام، 8 تطبيقات
  (Notepad / Paint / My PC / System Monitor / About / DOS shell / Speaker / **NovaBASIC**)،
  مؤشر ماوس برمجي، خط 8×8.

### NovaBASIC — لغة برمجة حقيقية داخل الجهاز

تطبيق BASIC مكتوب داخل النواة، بمفسّر خاص به (لا يعتمد على DOS). اضغط `b` على سطح المكتب
أو اكتب `basic` في موجه الأوامر، ثم اكتب في سطر `BASIC>`:

| الأمر | الوظيفة |
| --- | --- |
| `RUN` | يشغّل البرنامج التجريبي (يرسم على إطار 16×16 ويعزف نغمة) |
| `SAMPLES` | يبدّل بين ثلاثة برامج جاهزة |
| `HELP` | قائمة الكلمات المفتاحية |
| `CLS` / `NEW` | يمسح الشاشة |
| أي نص آخر | يُنفَّذ كبرنامج BASIC |

الكلمات المفتاحية: `PRINT "…"`، `PSET x,y`، `LINE y`، `BEEP`، `LAUNCH paint|monitor|notepad|files|music`،
`END`، `REM`. النتائج تظهر فوراً في لوحة 16×16 (كل خلية 5 بكسل) وفي سجل الشاشة.

### NovaFS — ملفات تبقى بعد إعادة التشغيل

الجهاز يُقلع من قرص مرن، ويسحب **قرص بيانات IDE سعة 4 MB** كقرص ثانٍ. النواة تفرمته تلقائياً
بنظام ملفات بسيط اسمه **NovaFS** (سوبربلوك + دليل 64 ملفاً + مساحة بيانات 120 KB)، فتظل الملفات
موجودة بعد إعادة تشغيل الجهاز:

| الأمر | المكان | الوظيفة |
| --- | --- | --- |
| `SAVE prog.bas` | BASIC | يحفظ البرنامج الحالي على C: |
| `LOAD prog.bas` | BASIC | يقرأ الملف ويشغّله |
| `FILES` / `DIR` | BASIC | يسرد ملفات القرص |
| `DIR` | موجه الأوامر | سرد الملفات بأحجامها |
| `TYPE name` | موجه الأوامر | يطبع محتوى الملف |
| `DEL name` | موجه الأوامر | يحذف ملفاً |
| `FORMAT` | موجه الأوامر | يفرمت القرص من جديد |

واجهة «جهاز الكمبيوتر» تعرض الملفات الحقيقية من القرص.

**الحفظ التلقائي:** القرص كامل (4 MB) يُخزَّن في **IndexedDB**، فيُسترجع قبل إقلاع الجهاز مباشرة:
أعد تحميل الصفحة أو أغلق التطبيق وارجع — ملفاتك موجودة. الحفظ يتم كل 8 ثوانٍ، وعند إخفاء
الصفحة أو إغلاقها، وقبل أي إعادة تشغيل. لو المتصفح لا يسمح بـ IndexedDB (تصفح خاص مثلاً)
يقلع الجهاز عادي بقرص فاضي بلا أي رسالة خطأ.

ما زال بإمكانك أخذ نسخة يدوية: زر **حفظ الملفات** ينزّل `nova-disk.img`، وزر **مسح ملفات الجهاز**
يعيدك لقرص فارغ (بعد حذف النسخة المحفوظة).

اختصارات لوحة المفاتيح على سطح المكتب: `b` BASIC، `d` موجه الأوامر، `m` المراقب، `p` الرسم.
`Esc` يعيد لوحة المفاتيح لسطح المكتب.
- `build.sh` — `as` + `gcc` + `ld` + `objcopy` ← `nova-desk.img` (قرص مرن 1.44MB).

إعادة البناء: `cd os-image && ./build.sh` ثم انسخ `nova-desk.img` إلى `public/images/`.

## أنظمة جاهزة

- **NovaDesk** — نظامنا، يُبنى من `os-image/` (يعمل بالكامل: نوافذ، تطبيقات، ماوس، صوت).
- **FreeDOS boot disk** — قرص DOS حر (GPL) يعمل فعلياً: `DIR`، `VER`، `VOL` … أوقف المؤشر على الشاشة
  ثم استخدم الصندوق أسفلها لإرسال الأوامر (بعض الأنظمة تحتاج Enter، ولذلك يوجد زر «إرسال ⏎»).

## رموز BIOS/VGA

`public/roms/` يحوي SeaBIOS و Bochs VGA BIOS (رخص مفتوحة، من مستودع v86) — لا توجد أي ملفات نظام تجارية.

- `os-image/screenshot.png` — لقطة من ذاكرة VBE الخاصة بالجهاز بعد إقلاع NovaDesk.
- `os-image/nova-basic-typed.png` و `nova-basic-run.png` — إدخال `run` من لوحة مفاتيح PS/2 حقيقية
  داخل VM، ثم تنفيذها: النص يظهر في السطر و الرسم يظهر في لوحة 16×16.
- `os-image/canvas-check.png` — لقطة من **canvas الخاص بـ v86** (نفس المسار الذي يرسم في المتصفح)،
  أُخذت من تشغيل headless: 343 إطارًا، بلا ارتفاع في الذاكرة (≈17MB).
- FreeDOS: تم التحقق فعليًا بتنفيذ `VOL` وإظهار `Volume in Drive A is FREEDOS`.

## تشغيل التطبيق

```bash
npm install
npm run dev     # http://localhost:5173
```

ثم: سطح المكتب ← أيقونة **محاكي الحاسوب** ← «تشغيل الجهاز».

## لماذا محاكي كامل وليس Wine؟ (مقارنة مع Winlator / Mobox / GameHub)

هناك عائلتان مختلفتان لتشغيل برامج ويندوز على أندرويد، ونحن اخترنا الثانية بوعي:

| | **توافق API** (Winlator، Mobox، GameHub) | **محاكاة عتاد كاملة** (مشروعنا) |
| --- | --- | --- |
| الفكرة | Wine يترجم استدعاءات ويندوز إلى لينكس، وBox64 يترجم x86 إلى ARM | جهاز PC كامل: BIOS + معالج + شاشة + أقراص، والنظام الأصلي يعمل كما هو |
| السرعة | عالية (ترجمة ثنائية، وأحياناً JIT) | أبطأ (تفسير/JIT داخل WebAssembly) |
| ما يعمل | تطبيقات .exe للـ32/64-bit | أنظمة كاملة: DOS، Win 3.1/95/98، وأي شيء يقلع من قرص |
| التشغيل على سطح المكتب | صعب | يعمل في المتصفح وفي أندرويد بنفس الكود |
| الترخيص | GPL-2.0 (Winlator) / مغلق (GameHub) — GPL يفرض فتح مصدر تطبيقنا بالكامل | v86 BSD، نواتنا ملكنا، لا قيود على طريقة التوزيع |
| التحكم في العتاد | محدود بما يسمح به Wine | كامل: نكتب BIOS ولوحة المفاتيح والشاشة بأنفسنا |

**لماذا لا نستخدم Winlator أو Boxedwine هنا؟** لأنهما GPL-2.0، ودمجهما في هذا التطبيق يفرض ترخيص المشروع
كله بـGPL. ولأن هدف المشروع تعليمي/تحكمي: نريد جهازاً نفهمه ونملكه من قطعة الإقلاع حتى النافذة.
أما فكرة Wine نفسها فمثبتة عملياً في المتصفح (Boxedwine + Wine 1.7.55، وbassdrum4/windowsappplayer،
وShubin123/exebrowser)، وهي مرشح قوي لمسار **«تشغيل .exe مباشرة»** في مرحلة لاحقة — بشرط قبول GPL
أو بناء بديل نظيف.

## أين تقف أندرويد نفسها من هذا؟

- **AVF / pKVM**: أندرويد 13+ يوفّر تعتيماً حقيقياً (crosvm + pKVM)، لكن AOSP يشترط أن تكون الصور
  موقّعة من Google أو الشركة المصنّعة، وأن تكون صلاحية طلب الآلات المحمية محصورة بتطبيقات موقّعة بمفتاح
  المنصة. يعني: **لا يمكن لتطبيق عادي (حتى مع root) أن يبني «نواة ويندوز فرعية» عبر AVF**. مشاريع مثل
  PocketVM تعمل فقط بتعديل SELinux/ADB وبناء مخصص.
- لذلك المسار الصحيح لتطبيق على كل الأجهزة هو **محاكي داخل فضاء المستخدم** (ما نفعله)، مع الاستفادة من
  AVF في المستقبل على الأجهزة التي تسمح به.

## ما لا يمكن عمله

- المحاكي 32-bit Pentium-class: DOS، Windows 3.1/95/98 وأمثالها تعمل؛ Windows 10/11 والتطبيقات 64-bit لا.
- لا يمكن استبدال نواة أندرويد نفسها؛ المحاكي طبقة داخل التطبيق.
- لا تُضمَّن أنظمة تجارية: استخدم NovaDesk المرفق أو صورة تملك حق استخدامها.
- لا يمكن قتل تطبيقات أندرويد الأخرى لتفريغ الموارد؛ المتاح هو أن **يتنازل تطبيقنا** عن موارده
  (تقليص ذاكرة الجهاز، خفض الإطارات، التجميد في الخلفية) — وهو ما سنبنيه في «حاكم الموارد».
